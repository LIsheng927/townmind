feat(planner): 规划层 + 事件驱动的门——日程让小镇像真的，日程的数据暴露了成本门的盲区

规划层（Generative Agents 缺的第三件）：
  townmind/planner.py：游戏时钟（600 秒一天，开服 7 点）、日程结构（地点 Literal 枚举、
  时段不重叠）、按工作地点拼的模板兜底、每人每游戏日一次大模型生成。没事发生时按日程
  行动而不是随机闲逛；提示词带"现在几点、按日程你在哪干什么"。
  真实数据（5 分钟 × 3 seed）：去过的地点 5.3 -> 2.7，91% 时间在该在的地方，10/10 日程
  符合人设（evals/plan_samples.py）。但成本没降（80 -> 75/min）：岗位成对，日程把
  Alice/Iris、Bob/Greta 锁在一起一整天，"附近有人就问模型"的门就一整天开着。
  门判断的是有没有人，不是有没有事——这是这一轮最值钱的发现。

事件驱动的门（event_gate）：有人说话 / 有人新来（60 秒没见过）/ 有任务 / 隔 90 秒主动一次
  才问模型。四配置消融：每分钟调用 full 80 / plans 75 / gate 38 / plans_gate 26，输入
  token 73 万 -> 25 万；代价是说话 215 -> 132 -> 74、被回应率 90% -> 87.5% -> 85.5%；
  重复率 3.1% -> 0.5%，砍掉的是废话。服务里默认开（main.py），Agent 构造默认关作消融基线。

顺手修的两个真问题：
  - 模型不遵守 tool schema 枚举，4/10 日程把 place 写成"家"——校验前归一化（coerce_places）
    + 提示词明说没有家；改完 10/10 一段不用修。枚举是提示不是约束，校验得自己做。
  - OpenAI 429 撞 TPM 上限退回行为树污染评测——按服务端等待时间退避重试，失败率 3.5% -> 0。
